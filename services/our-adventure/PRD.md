> **핵심 포지셔닝 (확인 필요)**: 원래 아이디어는 "여행 위치에 따라 코스를 만들어주는 서비스"에서 출발했다.
> 이 초안은 핵심 가치를 코스 생성이 아니라 **"그룹이 함께 남긴 스팟 기록 → 자동 리포트 → 공유"** 루프에 둔다.
> 코스 계획은 지도 앱, 여행 플래너가 이미 잘하는 영역이라 차별화가 어렵고, 그룹 공동 기록과 결과물 자동 완성은 비어 있는 자리이기 때문이다.
> AI 코스 초안은 MVP에서 제외하고, 파일럿 기간에는 운영자가 수동으로 코스를 만들어 주는 컨시어지 방식으로 수요만 측정한다 (H4).

## 1. Problem

- **누구의** 문제인가: 10~40명 그룹을 하루~2박3일 일정으로 인솔하는 사람. 중·고등학교 교사(담임, 동아리, 체험학습 담당), 방과후/학원 강사, 성인 소모임 리더. 참여자(학생, 동아리원)는 페인이 약하고 "귀찮지 않으면 남긴다"는 수준이라, 참여 마찰이 곧 서비스 성패를 가른다.
- **어떤** 문제인가: 그룹 여행은 계획은 한 사람이 떠안고, 기록은 흩어지고, 결과 정리는 아무도 하지 않는다.
  - 계획: 인솔자가 지도 앱, 블로그, 엑셀을 오가며 동선을 짜고, 참여자는 코스를 모른 채 따라간다.
  - 기록: 사진은 각자의 갤러리와 단톡방에 흩어지고, 어디서 무엇을 느꼈는지는 남지 않는다.
  - 결과: 체험학습 보고서, 학부모/학교 공유, 단체 앨범 정리는 다시 인솔자의 수작업이 되고, 대부분은 결국 하지 않는다.
- **현재 우회 방법**:

| 대체재 | 잘하는 것 | 못하는 것 |
|---|---|---|
| 카카오톡 단톡방 + 앨범 | 모두 이미 사용, 즉시 공유 | 장소/순서 맥락 없음, 코멘트가 대화에 묻힘, 결과물로 남지 않음 |
| 구글 포토 공유 앨범 | 사진 모으기 | 장소별 구조, 코멘트, 코스 연결 없음 |
| Padlet (지도형 보드) | 교사들이 실제로 체험학습에 사용, 위치+글+사진 | 현장 모바일 경험이 무겁고 코스 개념 없음, 무료 제한 |
| Polarsteps | 위치 기반 자동 여행 기록, 결과물 퀄리티 | 개인 여행 중심, 그룹 공동 기록과 인솔자 통제 없음 |
| 트리플 / 네이버 지도 저장 | 코스와 장소 계획 | 여행 중 기록과 결과 공유 없음 |

- **차별화가 우리 컨텍스트에 맞는가**: Polarsteps의 "자동 결과물"과 Padlet의 "교사가 쓰는 위치 기반 공동 보드"를 합친 자리다. 둘 다 이미 수요가 증명됐지만, 한국 그룹 여행의 기본 채널인 카카오톡에서 링크 하나로 전원이 참여하는 경험은 비어 있다. 반대로 Polarsteps식 자동 경로 추적은 학생 위치 추적 리스크 때문에 우리 타깃에는 맞지 않아 가져오지 않는다.
- **왜 지금**인가:
  - 학교 현장체험학습과 수학여행이 정상화되면서 교사의 인솔, 기록, 보고 부담이 다시 커졌다.
  - 생성형 AI로 "흩어진 사진과 한 줄 코멘트 → 읽을 만한 요약" 변환 비용이 거의 0이 되었다.
  - 모바일 웹만으로 카메라, 위치, 공유가 충분해 앱 설치 없이 그룹 전체를 참여시킬 수 있다.
- **Builder OS 연결**: 위치 + 미디어 업로드 + 가입 없는 그룹 참여 + AI 요약은 이후 서비스(GPS Journal 등)에 재사용할 블록이다. 파일럿 모집 랜딩은 Homepage Builder를 재사용해 TTFU를 줄인다.

### Beachhead (권고)

**만 14세 이상 그룹(중·고교 동아리/체험학습, 성인 소모임)으로 시작하고 초등학생은 MVP에서 제외한다.**
만 14세 미만은 개인정보 수집 시 법정대리인 동의가 필요해 "가입 없는 참여" 원칙과 충돌한다.
트레이드오프는 수요가 가장 큰 초등 체험학습 시장을 늦추는 대신 검증 속도와 법적 리스크를 줄인다는 것이다.

## 2. Hypotheses & Risks

리스크가 큰 순서다. MVP는 H1~H3을 검증하기 위해 존재한다.

| ID | 가설 (믿고 있는 것) | 틀렸을 때 영향 | 검증 방법 |
|---|---|---|---|
| H1 | (가치) 참여자는 가입/설치 없이 링크만 있으면 현장에서 스팟 기록을 남긴다 | 리더 혼자 쓰는 앨범이 되어 그룹 서비스 가치가 무너진다 | 파일럿 참여율 측정. 통과: 초대 인원 중 기록 1개 이상 ≥ 50% |
| H2 | (가치) 자동 생성 리포트는 공유하고 싶은 수준이다 | 단톡방 앨범보다 나을 게 없다 | 리포트 공유율 + 리더 인터뷰. 통과: 종료 72시간 내 공유 ≥ 40% |
| H3 | (도달) 공유된 리포트를 본 외부인과 리더가 다음 여행을 만든다 | 일회성 이벤트 도구가 되어 확산과 리텐션이 없다 | 외부 방문 → 여행 생성 전환, 리더 재생성 추적. 통과: 90일 내 재사용 ≥ 25% |
| H4 | (가치) AI 코스 초안이 리더의 계획 시간을 의미 있게 줄인다 | 코스 기능은 지도 앱으로 충분하다 | MVP에선 컨시어지로 수요만 측정. 통과: 코스 초안 요청률 ≥ 50% |
| H5 | (도달) 학교가 학생 사진 기록 도구 사용을 허용한다 | 학교 시장 진입 불가, 성인 그룹 중심으로 전환 | 교사 5명 인터뷰, 학교 지침 확인. 통과: 사용 가능 응답 ≥ 3/5 |

| Risk | 유형 (Value / Usability / Feasibility / Business) | Mitigation |
|---|---|---|
| 학생 사진/위치 데이터의 개인정보 리스크, 학교 승인 장벽 | Business | 만 14세 미만 제외, 실명/연락처 미수집, EXIF 위치 제거, 기본 비공개, H5 사전 인터뷰 |
| 리더만 쓰고 참여자는 안 씀 | Value | 가입 없는 참여, 10초 기록 UX, 스팟 도착 시 단톡방에 붙여넣을 "기록 요청" 문구 제공 |
| 결과물이 단톡방 앨범과 차별화되지 않음 | Value | 지도+순서+코멘트 중심 레이아웃, AI 요약, 파일럿 후 리포트 형식 반복 개선 |
| 카카오톡 인앱 브라우저의 카메라/업로드 호환성 | Feasibility | 개발 첫 주 기술 스파이크, 실패 시 외부 브라우저 열기 안내 |
| 처음 쓰는 참여자가 기록 방법을 모름 | Usability | 첫 진입 시 코스와 "기록하기" 버튼 하나만 노출, 파일럿 관찰 |
| 부적절한 사진/코멘트 | Business | 리더 삭제 권한, 비공개 기본값, 신고 시 24시간 내 처리 |
| 체험학습은 연 1~2회라 리텐션이 낮음 | Business | 연간 일정이 많은 동아리/학원/소모임을 파일럿에 포함, H3 별도 측정 |

## 3. Success Metrics

파일럿 기준: 실제 그룹 여행 8~10건 (중·고교 4~5건, 성인 소모임 4~5건), 4~6주.

| 구분 | 지표 | 목표 | 측정 방법 |
|---|---|---|---|
| North Star (가설 검증) | 공유된 리포트 수: 참여자 3명 이상이 기록하고 외부 공유가 1회 이상 일어난 여행 | 파일럿 여행의 40% 이상 | `record_created`의 고유 참여자 수 + `report_shared` 이벤트 |
| 보조 (H1) | 참여율: 참여자 중 기록 1개 이상 남긴 비율 | ≥ 50% | `member_joined` 대비 `record_created` 고유 참여자 |
| 보조 (H1) | 기록 소요시간: 기록 화면 진입 → 완료 중앙값 | ≤ 15초 | `record_created`의 duration 속성 |
| 보조 (H2) | 리포트 공유율: 종료 72시간 내 공유된 여행 비율 | ≥ 40% | `trip_ended`와 `report_shared` 시간 차 |
| 보조 (H3) | 리더 재사용: 90일 내 두 번째 여행 생성 비율 | ≥ 25% | 리더별 `trip_created` 횟수 |
| 보조 (H3) | 리포트당 외부 방문 수 | ≥ 5 | `report_viewed` 중 비참여자 세션 |
| Guardrail (지켜야 할 선) | 사진 업로드 실패율 | < 2% | 업로드 성공/실패 이벤트 |
| Guardrail (지켜야 할 선) | 개인정보/부적절 콘텐츠 삭제 요청 처리 | 발생 시 100% 24시간 내 처리 | 신고 로그 |

여행 1건당 인프라 + AI 비용도 함께 기록한다. 이후 수익 모델 판단의 근거로 쓴다.

- **Kill Criteria**:
  - 참여율 < 30%: 그룹 공동 기록 가설 실패. 리더 1인 기록 + 자동 결과물 도구로 축소하거나 중단한다.
  - 참여율은 충분하지만 공유율 < 20%: 결과물 품질 문제. 기능 추가를 멈추고 리포트 형식(PDF, 요약 카드 등)부터 개선한다.
  - H5 실패(학교 사용 불가): 성인 소모임/기업 워크숍으로 타깃을 전환한다.

## 4. MVP Scope

> 위 지표를 검증하는 데 꼭 필요한 것만 포함한다. Impact는 North Star와 H1~H3 기여도, Effort는 2주 스프린트 기준 상대 공수(S/M/L)다.

| 포함 | 검증하는 가설 | Impact | Effort |
|---|---|---|---|
| 가입 없는 참여: 링크/QR/6자리 코드 + 닉네임 | H1 | 높음 | S |
| 스팟 기록: 사진 1~3장 + 한 줄 코멘트(80자) | H1 | 높음 | M |
| 위치 기반 가까운 스팟 자동 선택 | H1 (기록 소요시간) | 중간 | S |
| 수동 코스 만들기: 장소 검색으로 스팟 추가, 순서 변경 | H1 (기록을 붙일 뼈대) | 중간 | S |
| 여행 중 그룹 피드 (스팟별/시간순, 지도) | H1 | 중간 | S |
| 여행 종료 시 자동 리포트 + AI 요약 1단락 | H2 | 높음 | M |
| 리포트 공유 링크 + 공개 범위 설정 | H2, H3 | 높음 | S |
| 리더 계정과 내 여행 목록 | H3 (재사용 측정) | 중간 | S |
| 리더 모더레이션, EXIF 제거 | H5 (학교 신뢰 조건) | 중간 (Guardrail) | S |
| Analytics 이벤트 수집 | 전체 | 높음 | S |

| 제외 (이번에 안 함) | 이유 |
|---|---|
| AI 코스 초안 생성 | Impact 중간, Effort M, 차별화 낮음. 컨시어지로 H4 수요를 먼저 본다 (P1 후보) |
| 체험학습 보고서 PDF 내보내기 | 교사 리텐션 레버일 수 있으나 파일럿 인터뷰로 수요 확인 후 결정 (P1 후보) |
| 경로 최적화, 이동시간 계산 | Effort L, 지도 앱이 이미 잘한다 (P2) |
| 실시간 위치 추적, 인원 체크 | 안전 책임과 개인정보 리스크 대비 검증 가치가 낮다 |
| 댓글, 좋아요, 채팅 | 단톡방과 경쟁하게 되고 핵심 가설과 무관하다 |
| 네이티브 앱, 오프라인 모드, 영상, 다국어 | 모바일 웹으로 가설 검증이 가능하다 |
| 만 14세 미만 사용, 학교 LMS 연동 | Beachhead 밖이며 법정대리인 동의 플로우가 필요하다 |
| 결제/요금제 | 가치 검증 전이다. 비용 데이터만 수집한다 |

## 5. User Flow

```text
[인솔자]
여행 만들기(이름, 날짜, 지역) → 스팟 추가로 코스 구성 → 참여 링크를 단톡방에 공유
→ 여행 중 피드 확인 → 여행 종료 → 리포트 확인 → 리포트 공유 → 성공

[참여자]
링크/QR 열기 → 닉네임 입력 → 코스 확인
→ 스팟 도착 → 기록하기(촬영 + 한 줄, 10초) → 여행 후 리포트 열람/공유
```

## 6. Requirements

| ID | Requirement | Priority | 수용 기준 |
|---|---|---|---|
| FR-001 | 리더는 이메일 매직링크 또는 소셜 로그인으로 계정을 만든다 | Must | 신규 리더가 가입 후 1분 안에 여행 만들기 화면에 도달한다 |
| FR-002 | 리더는 여행(이름, 기간, 지역)을 생성/수정/삭제한다 | Must | 삭제된 여행의 리포트 링크는 404를 반환한다 |
| FR-003 | 리더는 장소 검색으로 스팟을 추가하고 순서를 바꾼다 | Must | 스팟 30개까지 추가되고, 순서 변경이 참여자 화면에 새로고침 없이 반영된다 |
| FR-004 | 여행별 참여 링크, QR, 6자리 코드를 발급하고 재발급한다 | Must | 재발급 후 이전 링크/코드로는 신규 참여가 거부된다 |
| FR-005 | 참여자는 닉네임만으로 참여하고 같은 기기 재방문 시 세션이 유지된다 | Must | 연락처/실명 입력 필드가 없고, 브라우저 재시작 후에도 같은 참여자로 인식된다 |
| FR-006 | 참여자는 스팟에 사진 1~3장과 80자 이하 코멘트를 남긴다 | Must | 4장째 사진과 81자째 입력은 막히고, 4G에서 업로드 후 5초 안에 피드에 보인다 |
| FR-007 | 기록 화면은 반경 300m 안의 가장 가까운 스팟을 기본 선택한다 | Must | 위치 권한 거부 시 스팟 목록 선택으로 대체되고 기록은 정상 저장된다 |
| FR-008 | 스팟에 속하지 않는 자유 기록을 남길 수 있다 | Must | 자유 기록은 리포트에서 시간순 위치에 표시된다 |
| FR-009 | 업로드 사진은 리사이즈되고 EXIF 위치정보가 제거된다 | Must | 저장된 원본 파일에 GPS EXIF 태그가 없다 |
| FR-010 | 여행 피드는 그룹 기록을 스팟별/시간순으로 보여주고 지도에 표시한다 | Must | 다른 참여자의 기록이 30초 안에 피드에 보인다 |
| FR-011 | 리더가 종료하거나 종료일 다음 날 00시가 되면 리포트가 자동 생성된다 | Must | 두 조건 모두에서 리포트가 생성되고 리더에게 링크가 보인다 |
| FR-012 | 리포트는 코스 지도, 스팟별 사진/코멘트, 통계, AI 요약 1단락을 포함한다 | Must | AI 요약 실패 시 요약 없이 리포트가 정상 표시된다 |
| FR-013 | 리더는 공개 범위(참여자만 / 링크가 있는 사람)를 설정하고 링크를 복사한다 | Must | "참여자만" 상태에서 비참여 세션은 리포트를 볼 수 없다. 모든 리포트는 noindex다 |
| FR-014 | 리더는 모든 기록을, 참여자는 자신의 기록을 삭제한다 | Must | 삭제된 기록은 피드와 리포트에서 즉시 사라진다 |
| FR-015 | 아래 Analytics 이벤트를 수집한다 | Must | 파일럿 여행 1건으로 Success Metrics 표의 모든 지표를 계산할 수 있다 |
| FR-016 | 리더는 지역/기간/그룹 성격을 입력해 AI 코스 초안을 받고 편집한다 | Could (P1) | H4 검증 후 정의 |
| FR-017 | 리더는 리포트를 PDF로 내보낸다 | Could (P1) | 파일럿 인터뷰 후 정의 |

Analytics 이벤트 (FR-015): `trip_created`, `spot_added`, `invite_shared`, `member_joined`, `record_created`(spot_id 유무, duration), `upload_failed`, `trip_ended`, `report_viewed`(참여자/외부 구분), `report_shared`, `trip_created_from_report_visit`

### Non-functional

- Performance: 기록 화면 진입 2초 이내(4G), 업로드 실패 시 자동 재시도
- Accessibility: 큰 터치 영역, 코멘트를 이미지 대체 텍스트로 사용, WCAG AA 대비
- SEO: 랜딩 페이지만 대상, 리포트와 여행 페이지는 모두 noindex
- Mobile: 모바일 웹(PWA) 우선, 카메라 직접 촬영 지원. iOS Safari 16+, Android Chrome 최신 2개 버전, 카카오톡 인앱 브라우저
- Security: 참여자 실명/연락처 미수집, 비공개 리포트는 추측 불가 토큰 URL, EXIF 위치 제거

## 7. Technical Notes

`engineer` agent가 작성한다. PM 관점의 제약만 미리 적는다.

- 국내 장소 검색 정확도를 위해 카카오 또는 네이버 지도/장소 API를 우선 검토한다.
- AI에는 코멘트 텍스트와 스팟명만 보낸다. 사진 이미지는 MVP에서 AI로 보내지 않는다 (비용, 개인정보).
- 리더는 계정, 참여자는 여행별 익명 세션이다.
- 개발 첫 주에 카카오톡 인앱 브라우저 촬영/업로드 스파이크를 먼저 한다.
